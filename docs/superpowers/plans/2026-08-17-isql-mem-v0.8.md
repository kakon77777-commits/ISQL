# ISQL-MEM v0.8 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add one-hop coordinate delta frames and random-access block decode on top of v0.7 native ISQL memory while preserving all existing formats byte-for-byte.

**Architecture:** Keep `ISN7` as the standalone canonical memory frame. Add `ISD8` as an optional one-hop locality representation referencing an exact `ISN7` base by SHA-256. Use canonical per-block `COPY / DELTA / REPLACE` modes and choose delta only when it is smaller than standalone native.

**Tech Stack:** Python 3.11+, standard library only, `unittest`, existing v0.7 native/spectral runtime.

## Global Constraints

- No human-readable representation is canonical.
- Delta chains are depth 1 only in v0.8.
- v0.7 `ISN7` bytes must remain unchanged.
- Stable source address remains content-derived and independent of locality representation.
- Registry IDs remain append-only.
- Unknown or noncanonical frames fail closed.
- Full and partial delta decode must produce identical target coordinates.
- Production changes follow RED → GREEN TDD.
