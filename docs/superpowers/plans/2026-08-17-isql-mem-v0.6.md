# ISQL-MEM v0.6 Physical Digit Carrier Packing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add deterministic BCD4 and D40 binary carriers for existing digits-only ISQL wires without changing any canonical v0.4/v0.5 wire.

**Architecture:** Introduce a transport-only `carrier.py` module. Canonical numeric wires remain ASCII digits and are first-class identities; carriers are reversible physical representations with an explicit codec frame and CRC32. Both memory numeric wires and hierarchical registry wires use the same generic carrier API.

**Tech Stack:** Python 3.11+, standard library only, `unittest`, raw binary files for carrier artifacts.

## Global Constraints

- Existing numeric memory wire and registry wire encoders are unchanged.
- No new memory profile.
- Carrier input is ASCII digits only.
- BCD4 and D40 must preserve leading zeros exactly.
- D40 uses 12 decimal digits per 5 bytes for full blocks.
- Carrier framing is deterministic and fail-closed.
- CRC32 is not cryptographic identity.
- TDD RED must precede each production behavior.
