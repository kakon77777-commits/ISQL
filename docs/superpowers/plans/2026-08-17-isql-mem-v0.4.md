# ISQL-MEM v0.4 Numeric Wire Encoding Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Compile v0.3 registry-backed spectral packets into a deterministic digits-only numeric wire carrier, add a backward-compatible `numeric` memory profile, and measure wire compaction without changing stable addresses or existing baseline/semantic/spectral codes.

**Architecture:** Keep `SemanticAnalysis` as the auditable authoring form and `SpectralPacket` as the typed registry-backed semantic packet. Add a `NumericWire` transport layer that serializes only protocol/version, registry revision/hash, integer spectral sequence, and an integrity checksum using a self-delimiting decimal integer codec. Add a fourth memory profile `numeric`; R1/R2 carry only the numeric wire while R4 preserves the existing exact-source contract.

**Tech Stack:** Python 3.11+, standard library only, `unittest`, UTF-8 digit strings, SHA-256 registry binding, CRC32 wire corruption guard.

## Global Constraints

- Wire alphabet is exactly ASCII digits `0-9`; no separators, Base64, hex, JSON punctuation, floats, or Unicode digits.
- Existing v0.3 baseline, semantic, and spectral codes must remain byte-for-byte unchanged.
- Stable `ISQL-ADDR` identity must not depend on numeric-wire encoding.
- The v0.4 wire binds the exact spectral registry revision and full 256-bit registry hash.
- CRC32 is only a corruption guard; it is not a cryptographic identity mechanism.
- Unknown magic/version, malformed lengths, non-canonical leading zeros, truncation, trailing digits, registry mismatch, and checksum mismatch fail closed.
- `registry_delta_bytes` remains measurement metadata and is not part of canonical wire semantics.
- R4 exact recovery behavior is unchanged.

**Files:**
- Create: `src/isql_core/wire.py`
- Create: `tests/test_numeric_wire.py`

**Interfaces:**
- `encode_uint(value: int) -> str`
- `decode_uint(text: str, pos: int = 0) -> tuple[int, int]`
- `encode_numeric_wire(packet: SpectralPacket) -> str`
- `decode_numeric_wire(wire: str) -> SpectralPacket`
- `compile_numeric_wire(packet: SpectralPacket) -> NumericWireCompileResult`

**TDD behaviors:**
- integer codec round-trips 0, one-digit, multi-digit, and 256-bit values;
- wire contains only digits;
- spectral sequence, registry revision, and registry hash round-trip;
- malformed/altered wire fails closed;
- decoded packet keeps `registry_delta_bytes=0` because cost metadata is external to semantic wire identity.
