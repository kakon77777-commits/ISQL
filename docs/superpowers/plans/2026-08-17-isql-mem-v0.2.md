# ISQL-MEM v0.2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Upgrade ISQL-MEM from a single deterministic R0–R4 representation to profile-aware multi-resolution memory where deterministic baseline and AI-assisted semantic-coordinate encodings can coexist under the same stable address and be compared transparently.

**Architecture:** Keep `ISQL-ADDR` immutable and source-derived. Introduce `MemoryVariant` profiles under one `MemoryRecord`; each variant owns its own R0–R4 `MemoryLayer` codes. Add a typed `SemanticCoordinateSet` plus an external/AI analysis contract, semantic R1/R2 encoders/decoders, profile comparison metrics, and CLI import/inspection commands. R4 exact recovery remains source-contract-only and cannot be upgraded by AI.

**Tech Stack:** Python 3.11+, standard library only, `unittest`, UTF-8 JSON, SHA-256.

## Global Constraints

- Stable address remains SHA-256 of exact source bytes and never depends on AI output.
- v0.1 memory records must remain readable by automatic migration to `baseline` profile.
- `baseline` and `semantic` profiles must be independently addressable by distinct MEM codes.
- Semantic coordinates are structured data, not executable code.
- External/AI analysis must disclose `analyzer_id` and `analyzer_contract`.
- R4 exact recovery semantics remain unchanged; AI output can never set `exact=true`.
- Deterministic baseline remains available for every encoded memory.
- Unknown profiles and malformed semantic coordinate payloads fail closed.
- No embeddings, external network calls, or model SDK dependencies are required by the core runtime.
