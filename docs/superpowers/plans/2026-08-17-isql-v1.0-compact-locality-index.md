# ISQL Core Runtime v1.0 Compact Locality Index Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the v0.9 JSON locality index on the runtime path with a compact `ILI1` machine-native index and bounded indexed candidate recall while preserving actual-ISD8-byte final selection and all prior wire formats.

**Architecture:** Add `compact_locality.py` beside the legacy `locality.py`. `ILI1` stores deduplicated registry bindings and compact entry/block metadata using raw hashes and canonical varints. Loading builds transient exact-block postings and sorted total-sum lookup tables; recall uses bounded indexed probes, while final selection still encodes top-k ISD8 candidates and compares actual bytes with standalone ISN7.

**Tech Stack:** Python 3.11+, standard library only, existing ISQL varint/native/delta primitives, `unittest`, SHA-256, CRC32.

## Global Constraints

- `ILI1` is derived speed infrastructure, not canonical memory.
- No embeddings or external ANN dependency.
- Heuristic recall never decides storage; actual ISD8 bytes do.
- v0.9 JSON locality index APIs remain compatible.
- v0.4 numeric wire, v0.5 registry wire, v0.6 D40, v0.7 ISN7, and v0.8 ISD8 bytes remain unchanged.
- Compact index decode fails closed on malformed/noncanonical data.
- Query candidate probing is bounded; final ISD8 reranking is exactly top-k or fewer.
- Runtime paths do not require human-readable index representations.
