# ISQL-MEM v0.5 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a derived hierarchical, exact, append-only-friendly compiler for the spectral registry and encode registry deltas as digits-only numeric wires without changing canonical spectral IDs or existing v0.4 memory wires.

**Architecture:** Keep `SpectralRegistry` authoritative. Add `hierarchical.py` with an exact reversible lexeme registry, value programs, revision deltas, and reconstruction validation. Add `registry_wire.py` for digits-only transport of hierarchical deltas. Integrate only authoring/inspection CLI and metrics; v0.4 numeric memory wire stays byte-for-byte stable.

**Tech Stack:** Python 3.11+, standard library only, `unittest`, UTF-8 JSON, existing prefix-free decimal uint codec.

## Global Constraints

- Preserve all v0.4 behavior and 104 baseline tests.
- Canonical `SpectralRegistry` IDs/revisions/hashes remain authoritative.
- Hierarchical compilation is derived and exactly reconstructable.
- Lexeme IDs are append-only within one hierarchical lineage.
- Existing spectral and numeric memory codes must not change.
- Registry wire must contain ASCII digits only and fail closed on corruption/hash mismatch.
- Report canonical JSON growth, structural delta, numeric wire, and shared/warm costs separately.
- R4 exact-source behavior is untouched.

## Self-review

The plan covers exact Unicode reconstruction, append-only semantic identity, hierarchical shared lexemes, incremental registry growth, numeric registry wire, fail-closed validation, compatibility, honest cold/warm accounting, and release evidence. It deliberately does not introduce learned tokenization, embeddings, trie optimization, cryptographic signing, or change v0.4 memory wire semantics.
