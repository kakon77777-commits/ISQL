# ISQL-MEM v0.7 Machine-Native Canonical Representation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make a deterministic binary native memory frame the canonical machine representation of ISQL spectral memory, eliminating decimal text from the primary encode/decode path.

**Architecture:** Add `isql_core.native` without modifying prior numeric/carrier formats. A native frame stores raw address digest, registry binding, resolution, and a block-bit-packed spectral integer sequence. Existing textual/numeric forms remain compatibility and debug views.

**Tech Stack:** Python 3.11+, standard library only, `unittest`, SHA-256, CRC32, canonical unsigned varints, block bit-packing.

## Global Constraints

- Package release becomes `0.7.0`.
- Human readability is not a canonical requirement.
- No native encode/decode path may depend on `encode_numeric_wire`, `decode_numeric_wire`, or decimal carrier codecs.
- v0.4/v0.5/v0.6 frozen wire/carrier fixtures remain byte-for-byte unchanged.
- Native frame unknown/corrupt/non-canonical inputs fail closed.
- Native decode verifies spectral registry revision/hash before semantic expansion.
