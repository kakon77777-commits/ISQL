# ISQL-MEM v0.5 Hierarchical Spectral Registry Compaction — Design

**Goal:** Reduce the remaining shared-registry cost without changing canonical spectral IDs, registry revisions, existing spectral/numeric memory codes, or R4 exact-source semantics.

## Design decision

v0.5 uses a **derived hierarchical registry compiler**, not a replacement canonical registry.

```text
Canonical SpectralRegistry (authoritative, append-only)
        ↓ deterministic compile
Lexeme Registry (shared exact text atoms)
        ↓
Value Programs (namespace value ID → lexeme ID sequence)
        ↓
Hierarchical Registry Delta / Snapshot
        ↓
Digits-only Registry Wire
```

The canonical `SpectralRegistry` remains the source of semantic identity. A hierarchical artifact is valid only if decoding it reconstructs the exact canonical registry revision and reproduces its SHA-256 content hash.

## Why this approach

Three approaches were considered:

1. Generic gzip/binary compression: easy and often compact, but structurally opaque and not ISQL-native.
2. Global trie/DAWG: strong prefix sharing, but append-only revision semantics and incremental patches become complex.
3. **Hierarchical lexeme interning + numeric deltas (selected):** exact, append-only-friendly, language-agnostic enough for v0.5, independently auditable, and naturally amortized across revisions.

## Layers

### L0 — Canonical semantic IDs

Unchanged v0.3 registry namespaces and stable value IDs.

### L1 — Lexeme registry

Registry strings are deterministically tokenized into exact reversible lexemes. Lexeme IDs are append-only and never reassigned.

Tokenizer contract:

- preserve exact Unicode text;
- preserve whitespace and punctuation as lexemes;
- group Unicode word runs;
- reconstruction by concatenation must be byte-identical UTF-8.

### L2 — Value programs

Each canonical value is compiled to a tuple of lexeme IDs:

$$
V_{n,i}=(\ell_1,\ell_2,\ldots,\ell_k).
$$

The pair `(namespace, canonical value ID)` remains identity. The lexeme program is only representation.

### L3 — Revision delta

Because the canonical registry is append-only, revision $r$ only needs to encode:

- new lexemes since $r-1$;
- new canonical values and their lexeme programs;
- target canonical revision/hash;
- previous hierarchical revision/hash.

### L4 — Numeric registry wire

The hierarchical delta/snapshot is encoded as digits-only numeric wire using the existing self-delimiting unsigned-integer codec, with a distinct registry magic/version and CRC32 corruption guard.

## Invariants

1. Canonical `SpectralRegistry` remains authoritative.
2. Existing canonical IDs never change.
3. Existing v0.4 numeric memory wire does not change.
4. Hierarchical artifacts must reconstruct exact UTF-8 registry values.
5. Reconstructed canonical registry hash must equal the embedded target hash.
6. Unknown/truncated/corrupt numeric registry wires fail closed.
7. Lexeme IDs are append-only within the hierarchical registry lineage.
8. A no-op canonical revision produces no hierarchical delta.
9. Cold cost and incremental/warm cost are reported separately.
10. Compression metrics never exclude required registry material without labeling it shared/preinstalled.

## Storage

```text
hierarchical_registry/
├─ current.json
├─ rev-000001.json
├─ rev-000002.json
├─ delta-000001.json
├─ delta-000002.json
└─ numeric/
   ├─ delta-000001.txt
   └─ delta-000002.txt
```

## Public interfaces

```python
compile_hierarchical_registry(canonical_registry, previous=None)
apply_hierarchical_delta(previous, delta)
reconstruct_spectral_registry(hierarchical_revision)
encode_registry_wire(delta)
decode_registry_wire(wire)
```

CLI:

```text
isql-core registry-compile-hierarchical
isql-core registry-decode-wire
isql-core registry-compare
```

## v0.5 experiment

Reuse the v0.4 three-memory corpus:

1. cold first registry;
2. identical vocabulary / no canonical growth;
3. partial new vocabulary.

Measure:

- canonical JSON registry bytes;
- canonical JSON delta bytes;
- new lexeme bytes;
- hierarchical structural delta bytes;
- digits-only registry wire bytes;
- cumulative cold total with memory wire;
- incremental partial-vocabulary total;
- exact canonical-registry reconstruction;
- memory coordinate fidelity.

v0.5 is successful if it demonstrates exact reconstruction and materially reduces at least the partial-vocabulary registry-growth cost. It does **not** require the first cold bootstrap to beat every generic compressor.
