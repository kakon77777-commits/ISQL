# ISQL-MEM v0.9 Locality Index and Automatic Base Selection — Design Spec

**Version:** v0.9 design  
**Date:** 2026-08-17  
**Base:** ISQL Core Runtime v0.8.0

## Goal

Automatically choose a useful standalone `ISN7` base for a new target memory without changing the `ISN7` or `ISD8` wire formats.

## Core rule

Candidate similarity is only a recall heuristic. The final objective is actual encoded bytes:

$$
oxed{b^*=rg\min_{b\in C_k}\left|\operatorname{ISD8}(b,t)ight|}
$$

and the runtime uses the delta only when:

$$
\left|\operatorname{ISD8}(b^*,t)ight|<|\operatorname{ISN7}(t)|.
$$

## Architecture

1. `LocalitySignature`: derived fixed/small block statistics for one standalone ISN7 frame.
2. `LocalityIndex`: rebuildable collection of signatures and frame references.
3. Candidate recall: deterministic score using registry match, item-count compatibility, exact block fingerprints, and coarse block statistics.
4. Exact reranking: load only the top-k candidate ISN7 frames and actually call `encode_delta_frame()`.
5. Selection: choose the smallest byte representation with deterministic SHA-256 tie-break; otherwise keep standalone ISN7.

## Signature

For every native block store:

- 64-bit SHA-256 fingerprint of the integer block;
- item count;
- integer sum;
- maximum value.

Frame-level fields:

- frame reference;
- frame SHA-256;
- source address digest;
- resolution;
- registry revision/hash;
- sequence item count;
- frame bytes.

No natural-language text or embedding is required.

## Candidate score

The recall score is lexicographically dominated by:

1. same registry hash;
2. exact block fingerprint count;
3. lower normalized block-sum distance;
4. lower item-count distance;
5. frame SHA-256 tie-break.

This score does not claim semantic identity and does not determine the final base.

## Invariants

- Index entries may reference only standalone `ISN7`, never `ISD8`.
- Index deletion must not lose canonical memory.
- Index rebuild over the same frame set is deterministic.
- Target frame itself is excluded by frame SHA-256.
- Final selection is based on actual bytes, not heuristic score.
- No multi-hop delta chain is introduced.
- `ISN7` and `ISD8` byte formats remain unchanged.
- Unknown/missing/corrupted base refs fail closed.

## CLI

Add:

- `locality-index-build --frames-dir DIR --index FILE`
- `locality-index-info --index FILE`
- `locality-select --index FILE --frames-dir DIR --target FILE --out FILE [--top-k N]`

`locality-select` writes either standalone `ISN7` or one-hop `ISD8` and reports the selected base when delta wins.

## Tests

- deterministic signature/index rebuild;
- candidate ranking on frozen v0.8 fixtures;
- exact reranking beats heuristic-only choice in a synthetic adversarial case;
- target self-exclusion;
- missing/corrupt base fail closed;
- fallback to standalone when every delta is larger;
- selected delta reconstructs target byte-for-byte;
- all v0.4-v0.8 frozen formats remain unchanged.

## Live experiment

Use frozen v0.8 R2 frames to test:

1. target #2 with #1/#3 bases — automatic selection should find a locality base and produce 87 B delta when available;
2. near-coordinate target — choose the most local base and beat standalone;
3. low-locality target #3 — fall back to standalone 126 B;
4. compare top-k actual selection against exhaustive oracle over the same candidate set.
