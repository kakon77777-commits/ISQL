# ISQL Core Runtime v1.0 — Compact Machine-Native Locality Index Design

**Status:** approved design for implementation  
**Date:** 2026-08-17  
**Base:** ISQL Core Runtime v0.9.0

## Goal

Replace the v0.9 JSON locality index on the AI runtime path with a compact machine-native derived index while preserving the two-stage base-selection rule:

$$
\boxed{
\text{indexed recall}
\rightarrow
\text{top-k candidate shortlist}
\rightarrow
\text{actual ISD8 byte rerank}
\rightarrow
\min(\text{ISD8},\text{ISN7})
}
$$

The index is speed infrastructure, never canonical memory. Deleting it must not destroy or change any `ISN7`, `ISD8`, address, registry, semantic, or spectral object.

## Non-goals

v1.0 does not:

- introduce embeddings or an ANN dependency;
- change ISN7 or ISD8 bytes;
- change v0.4 numeric wire, v0.5 registry wire, or v0.6 carrier bytes;
- make heuristic similarity authoritative;
- store full coordinates inside the locality index;
- create multi-hop delta chains;
- require human-readable runtime index data.

## Binary format

The new index file uses magic:

```text
ILI1
```

Logical object:

$$
I=(V,\mathcal R,\mathcal E,C),
$$

where:

- $V$ is the format version;
- $\mathcal R$ is a deduplicated registry-binding table;
- $\mathcal E$ is the sorted entry table;
- $C$ is a CRC32 integrity guard.

Every registry binding stores:

- registry revision as unsigned canonical varint;
- raw 32-byte registry SHA-256.

Every entry stores:

- UTF-8 `frame_ref` with canonical varint byte length;
- raw 32-byte frame SHA-256;
- raw 32-byte address SHA-256;
- one-byte resolution code (`R1` or `R2`);
- registry-binding table ID as canonical varint;
- item count as canonical varint;
- standalone frame byte count as canonical varint;
- block count as canonical varint;
- for each implicit block index:
  - item count as canonical varint;
  - raw 8-byte block fingerprint;
  - block value sum as canonical varint;
  - block value max as canonical varint.

The binary file does not store JSON field names or hexadecimal encodings.

## Canonicality

`ILI1` is deterministic for a fixed set of base frames.

Required invariant:

$$
\boxed{
\operatorname{encode}(\operatorname{decode}(b))=b
}
$$

for every valid compact index byte string $b$.

Decoder rejects:

- wrong magic/version;
- noncanonical varints;
- duplicate frame refs;
- noncanonical entry order;
- invalid registry-table IDs;
- invalid resolution codes;
- impossible block counts/item counts;
- truncation/trailing bytes;
- CRC mismatch;
- re-encoding mismatch.

## Derived runtime search structures

Loading `ILI1` builds transient in-memory structures that are not serialized as canonical content:

1. exact block postings keyed by `(resolution, block_index, fingerprint)`;
2. same-registry total-sum rows sorted by total coordinate sum;
3. per-resolution total-sum rows sorted by total coordinate sum.

For each entry:

$$
S(e)=\sum_j \operatorname{value\_sum}(B_j).
$$

These structures can always be reconstructed from `ILI1`.

## Candidate recall

For target $t$, candidate IDs come from three bounded sources:

1. exact-block posting hits;
2. nearest total-sum entries within the same registry binding;
3. nearest total-sum entries at the same resolution as fallback.

Candidate generation is capped by a deterministic probe budget:

$$
P = \max(k, k\cdot f),
$$

where $k$ is requested rerank size and $f$ is a small probe factor.

The target itself is excluded by frame SHA-256.

Heuristic ordering preserves the v0.9 signals:

- same registry first;
- more exact blocks first;
- lower normalized sum distance;
- lower item-count distance;
- frame SHA-256 deterministic tie-break.

The index may miss a global optimum for arbitrary adversarial corpora; therefore final byte-optimality claims are only made against the candidates actually recalled. Release validation separately compares compact recall against exhaustive oracle on frozen and synthetic corpora.

## Final selection

Recall never decides storage.

For every recalled candidate $b_i$:

$$
d_i=|\operatorname{ISD8}(b_i,t)|.
$$

Then:

$$
\operatorname{Select}(t)=
\begin{cases}
\operatorname{ISD8}(b^*,t), & \min_i d_i < |t|,\\
t, & \text{otherwise}.
\end{cases}
$$

Thus:

$$
\boxed{
\text{heuristic score}\neq\text{storage decision}
}
$$

remains a hard v1.0 invariant.

## Compatibility

v0.9 JSON locality indexes remain loadable and usable through legacy APIs and CLI commands.

v1.0 adds new machine-native commands rather than silently changing the meaning of existing JSON index files.

Frozen byte compatibility must hold for:

- v0.4 numeric memory wire;
- v0.5 numeric registry wire;
- v0.6 D40 carrier;
- v0.7 ISN7;
- v0.8 ISD8.

## CLI

Add:

```text
locality-native-build
locality-native-info
locality-native-select
```

`locality-native-build` consumes standalone `.isql7` frames and writes `.ili1`.

`locality-native-info` reports compact metadata and index SHA-256; JSON output is inspection only.

`locality-native-select` loads `.ili1`, performs bounded indexed recall, actual-byte reranking, and writes either ISD8 or ISN7.

## Release targets

For the existing 256-base synthetic corpus:

1. compact index must be materially smaller than v0.9 JSON index;
2. top-8 actual rerank must choose the same base and 92-byte ISD8 as exhaustive oracle;
3. actual rerank count remains 8/256;
4. compact index round-trip and CRC/canonicality tests pass.

For a larger synthetic corpus (target 4096 entries):

- build/load must succeed without external dependencies;
- query must use bounded candidate probing rather than linearly scoring every entry;
- actual ISD8 rerank remains top-k only.

No wall-clock performance claim is required because sandbox process timing is unstable; structural candidate counts are the release metric.

## v1.0 boundary

v1.0 closes the first ISQL memory-runtime loop:

$$
\boxed{
\text{semantic coordinates}
\rightarrow
\text{machine-native memory}
\rightarrow
\text{one-hop locality delta}
\rightarrow
\text{machine-native locality index}
\rightarrow
\text{automatic actual-byte base selection}
}
$$

The system remains explicitly experimental; v1.0 means the first internally coherent runtime architecture, not a claim of universal semantic compression or production security.
