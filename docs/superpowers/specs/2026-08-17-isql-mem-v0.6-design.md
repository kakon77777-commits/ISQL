# ISQL-MEM v0.6 — Physical Digit Carrier Packing Design

**Status:** Approved continuation design  
**Target runtime:** ISQL Core Runtime v0.6.0  
**Base:** v0.5.0 Hierarchical Spectral Registry Compaction

## Goal

Preserve the v0.4/v0.5 canonical digits-only numeric wires exactly, while adding a deterministic binary physical carrier that stores/transmits those decimal digits near their information density rather than at one ASCII byte per digit.

The core separation is:

$$
\boxed{
\text{Canonical Numeric Wire}
\neq
\text{Physical Packed Carrier}
}
$$

The packed layer must never redefine semantic IDs, registry revisions, memory profiles, or wire meaning.

## Architecture

```text
Semantic / Registry Structures
        ↓
Digits-only canonical numeric wire      ← unchanged v0.4/v0.5
        ↓
Physical carrier codec
        ├─ BCD4 baseline
        └─ D40 recommended
        ↓
Binary bytes for storage/transport
```

No fifth memory profile is introduced. The existing `numeric` profile remains canonical.

## Codec A — BCD4

Two decimal digits are stored in one byte. For an odd digit count, the unused low nibble is the sentinel `0xF` and must be validated during decode.

Expected payload ratio:

$$
\frac{1}{2}=50\%\ \text{of ASCII digit bytes}.
$$

BCD4 is the simple reference codec.

## Codec B — D40

D40 packs every 12 decimal digits into one unsigned 40-bit integer:

$$
10^{12}<2^{40}.
$$

Therefore:

$$
12\ \text{digits}\rightarrow5\ \text{bytes}.
$$

Expected payload ratio:

$$
\frac{5}{12}\approx41.67\%.
$$

The final partial block uses the minimum fixed byte width determined solely by the remaining digit count. Leading zeros are restored by zero-padding to the known decimal width.

## Carrier Frame

Binary frame:

```text
magic       4 bytes: IPC6
version     1 byte
codec       1 byte
length      canonical unsigned varint (decimal digit count)
payload     codec-dependent; length inferred from digit count
crc32       4 bytes, big-endian, over canonical ASCII digit wire
```

The frame stores no alternate semantic identity. It only packs the existing decimal sequence.

## Invariants

1. `unpack(pack(wire)) == wire` byte-for-byte.
2. Input wire must be non-empty ASCII `0-9` only.
3. Leading zeros are preserved.
4. Same wire + same codec produces identical carrier bytes.
5. Carrier decode rejects unknown magic/version/codec, malformed varints, truncated/trailing payload, invalid BCD nibbles, out-of-range D40 blocks, and CRC mismatch.
6. Existing v0.4 numeric memory wires remain byte-for-byte unchanged.
7. Existing v0.5 registry numeric delta wires remain byte-for-byte unchanged.
8. CRC32 is accidental-corruption detection, not cryptographic identity.
9. Inner wire validation remains authoritative for semantic integrity.

## API

```python
pack_digit_wire(wire: str, codec: str = "d40") -> bytes
unpack_digit_carrier(carrier: bytes) -> str
compile_digit_carrier(wire: str, codec: str = "d40") -> CarrierCompileResult
```

`CarrierCompileResult` reports:

- canonical wire bytes;
- carrier bytes;
- payload bytes;
- ratio;
- codec;
- SHA-256 of carrier bytes for artifact verification.

## CLI

```text
isql-core carrier-pack --wire <digits> --codec d40 --out carrier.bin
isql-core carrier-unpack --file carrier.bin
isql-core carrier-info --file carrier.bin
```

CLI output metadata may use JSON/hex hashes, but the carrier file itself is raw binary.

## Live Experiment

Run both BCD4 and D40 against:

1. v0.4 numeric memory wire;
2. v0.5 cold registry delta wire;
3. v0.5 warm/no-op case where applicable;
4. v0.5 partial-growth registry delta wire.

Measure:

$$
\rho_{\mathrm{carrier}}
=
\frac{\text{packed carrier bytes}}
{\text{ASCII numeric wire bytes}}.
$$

Also compare packed registry carrier bytes with the v0.5 hierarchical structural binary size. Do not claim packing beats the structural binary unless measured.

## Non-Goals

v0.6 does not change:

- semantic coordinates;
- spectral registry semantics;
- hierarchical registry semantics;
- numeric wire syntax;
- memory profile identities;
- compression of exact source content;
- cryptographic authentication.
